Задание №2 “Гибридный поиск и ранжирование в информационно-поисковых системах”

В рамках данного задания ваша задача построить гибридную поисковую систему на основе архитектуры “Retrieve & Re-Rank”, оценить качество поиска и влияние ранжирования на конечный результат.



Данные
Для начала нужно выбрать или собрать учебную коллекцию. Обычно коллекции очень большие (несколько миллионов документов), но поисковой индекс будет слишком большим, поэтому выберем "учебные" размеры
Ориентируйтесь на следующие размеры: минимум 100 тыс. документов и около 1 тыс. запросов (можно больше), для каждого из которых есть хотя бы один релевантный документ
Mr. TyDi (многоязычная коллекция, основана на Википедии). Запросы https://huggingface.co/datasets/castorini/mr-tydi и документы https://huggingface.co/datasets/castorini/mr-tydi-corpus - взять русский язык
Как сформировать выборку документов:
Если для теста (dev-а) указаны отрицательные документы (как, например, здесь https://huggingface.co/datasets/miracl/miracl/raw/main/miracl-v1.0-ru/qrels/qrels.miracl-v1.0-ru-dev.tsv ), то включите их в коллекцию
Если отрицательных документов в qrels нет или их недостаточно, и коллекция основана на Википедии, то прежде всего добавьте параграфы, которые относятся к той же статье Википедии (смотрите по заголовку title), что и положительные документы
Если и этого нет/недостаточно, то тогда рандом

Индексация и поиск кандидатов
Проиндексируйте коллекцию с помощью ElasticSearch
Найдите релевантные документы с помощью BM25 для запросов из Вашего датасета
Подсчитайте следующие метрики: Precision@5, Recall@5, MAP@5, MRR@5
Для подсчета метрик используйте https://github.com/joaopalotti/trectools  или https://huggingface.co/spaces/evaluate-metric/trec_eval 
Как считаются метрики можно посмотреть здесь: https://web.stanford.edu/class/cs276/19handouts/lecture8-evaluation-6per.pdf 
Чтобы повысить качество BM25 можете добавить лемматизацию или стемминг при индексации документов https://www.elastic.co/guide/en/elasticsearch/reference/current/analysis-lang-analyzer.html 
Зафиксируйте результат в таблице https://docs.google.com/spreadsheets/d/1TjY5P1Z6PQNSQDND1OAA-2M3ezDPkePPElWROpTcRwA/edit 


Ранжирование кандидатов
Для каждого вашего запроса выберите 50 документов с помощью BM25 и переранжируйте их одним из следующих способов:
Обучить собственный простой классификатор, который для пары запрос+документ предсказывал их релевантность (например, логистическая регрессия поверх tf-idf или эмбеддингов)
Взять модель для ранжирования из библиотеки SentenceTransformers. https://sbert.net/index.html Виды моделей для ранжирования:
Sentence Transformer -- отдельно кодируются запрос и документ, затем считается похожесть (обычно это 1 - косинусное расстояние) https://sbert.net/docs/sentence_transformer/usage/usage.html
Cross-Encoders -- одновременно кодируется пара запрос+документ https://sbert.net/examples/cross_encoder/applications/README.html 
Подсчитайте метрики для переранжированных документов
